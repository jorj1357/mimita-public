# Avatar Creator — Design Document

## Folder Structure

```
assets/avatars/
  <avatar_name>/
    avatar.json          # Avatar definition (auto-generated by the menu)
    face.png             # Simple mode: face image
    shirt.png            # Simple mode: shirt image
    pants.png            # Simple mode: pants image
    skin.png             # Simple mode: skin image
    head/                # Advanced mode: per-face overrides
      front.png / back.png / left.png / right.png / top.png / bottom.png
    torso/               # Advanced mode: per-face overrides
      ...
    left_arm/
    right_arm/
    left_leg/
    right_leg/
```

Users only need to know about the top-level folder. The menu handles everything.

## avatar.json Format

```json
{
  "name": "my_avatar",
  "version": 1,
  "simple": {
    "face": "face.png",
    "shirt": "shirt.png",
    "pants": "pants.png",
    "skin": "skin.png"
  },
  "advanced": {
    "head_front": "face.png",
    "head_back": "skin.png",
    "head_left": "skin.png",
    "head_right": "skin.png",
    "head_top": "skin.png",
    "head_bottom": "skin.png",
    "torso_front": "shirt.png",
    "torso_back": "shirt.png",
    "torso_left": "shirt.png",
    "torso_right": "shirt.png",
    "torso_top": "shirt.png",
    "torso_bottom": "shirt.png",
    "left_arm_front": "shirt.png",
    ...
    "left_leg_front": "pants.png",
    ...
    "right_leg_front": "pants.png",
    ...
  }
}
```

Simple mode expands to advanced mode via rules:
- `face` → head front
- `shirt` → torso all, arms all
- `pants` → legs all
- `skin` → head back/left/right/top/bottom

In advanced mode, per-face paths are resolved exactly. Unset faces fall back to simple mode values, then to skin color default.

## Runtime Architecture

### Core Files (`src/avatar/`)

| File | Purpose |
|------|---------|
| `avatar.h` | `AvatarDefinition` struct, `AvatarSystem` class |
| `avatar.cpp` | Atlas construction, UV remapping, hot reload, JSON serialization |
| `avatar-menu.h` | `AvatarMenuResult` + `drawAvatarMenu()` |
| `avatar-menu.cpp` | Avatar Creator menu UI with simple + advanced mode |
| `avatar-commands.h` | `registerAvatarCommands()` |
| `avatar-commands.cpp` | Terminal commands: create, list, load, apply |

### Data Flow

```
avatar.json
    ↓
AvatarSystem::loadAvatar()
    ↓
For each body part (6) × face direction (6):
  Resolve path → load PNG via stbi_load → blit into atlas buffer
    ↓
Generate 2000×2000 atlas texture (glTexImage2D)
    ↓
AvatarSystem::applyAtlasToPlayer()
  For each body part mesh:
    Compute face direction per triangle
    Remap UV → atlas cell coordinates (same math as OutfitAtlas)
    Assign atlas texture to all batches
```

## Texture Assignment System

The avatar system reuses the existing OutfitAtlas UV remapping approach.

### Atlas Layout

```
2000×2000 texture
6 rows (head, torso, leftArm, rightArm, leftLeg, rightLeg)
6 columns (TOP, BOTTOM, FRONT, BACK, LEFT, RIGHT)
Each cell: 313×313 pixels (309 usable with 2px inset)
Padding: 40px all sides, 8px gap between cells
```

### UV Remapping

For each triangle in a body part mesh:
1. Compute face direction from triangle normal
2. Choose atlas cell (row = body part, column = face direction)
3. Compute projected UV within the face's bounding box
4. Map projected UV to cell coordinates in atlas space

## Hot Reload System

`AvatarSystem::pollHotReload()` is called each frame:

1. Track `assets/avatars/<name>/` last write time (via `std::filesystem::last_write_time`)
2. On change: reload `avatar.json`, rebuild atlas texture, reapply to player
3. 250ms throttling to avoid re-reading during partial file writes

## Networking Plan

Phase 1 (MVP): Each client applies their local avatar to all player entities.

Phase 2: Extend HelloPacket to include avatar name:
```cpp
struct HelloPacket {
    PacketHeader header;
    char name[MAX_NAME_BYTES];
    char avatarName[MAX_NAME_BYTES];  // NEW
};
```

Remote clients receive avatar name during handshake. A new packet type `PACKET_AVATAR` can transmit the full avatar.json for custom/community avatars.

Future: Dedicated avatar download system with asset caching and hash verification.

## Future Extensibility

| Feature | Design |
|---------|--------|
| **Hats** | New avatar field `hats/` with same face-per-direction structure. Separate mesh attached to head node. |
| **Hair** | Similar to hats — mesh attached to head with alpha-blended textures. |
| **Backpacks** | Mesh attached to torso back. |
| **Capes** | Cloth-simulated mesh attached to shoulders. |
| **Weapon Skins** | Extend avatar.json with `"weapon_skins": {"revolver": "gold.png"}`. |
| **Marketplace** | Avatar name maps to marketplace item ID. Download on join. |
| **Sharing** | Export avatar as single `.mimica` file (zip of folder + json). |
| **Downloadable** | Remote avatar downloading via HTTP with local caching. |

All future features follow the same pattern:
1. Player sets `avatarName` in settings
2. On connect, send avatar name to server
3. Remote clients download/resolve avatar
4. Hot reload watches for changes
