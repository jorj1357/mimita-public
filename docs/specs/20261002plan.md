# Full Counter-Strike Mode Implementation Plan

## Summary

Implement the existing `counterstrike` gamemode as a complete JSON-controlled 5v5 round-based mode on `assets/maps/dust2cyberiav3.glb`.

Final acceptance:

```text
Start counterstrike
Choose Counter-Terrorists or Terrorists
Play as one actor
4 allied NPCs
5 opposing NPCs
70 FOV
Forced first-person
Heavy Counter-Strike movement
Revolver, shotgun, hitscan rifle, grenades
No damage numbers or hit markers
Blood, killfeed, and ragdolls enabled
Bomb pickup, planting, dropping, defusing, and explosion
NPC navigation, perception, combat, and objective behavior
Round score and match victory
```

The implementation must remain generalized:

```text
Gamemode rules own rounds and objectives.
Roles own team membership and actor capabilities.
Actor presets own actor configuration.
Behavior presets own AI policy.
Shared actor execution owns movement, weapons, damage, and physics.
```

`weapons.json` remains unchanged. Counter-Strike weapon values are applied as actor-preset overrides at runtime and must not overwrite base weapon definitions.

## Stage 2 — Implement team selection and 5v5 roster creation

Add terminal commands:

```text
team_list
team_pick 1
team_pick 2
```

`team_list` must enumerate the active mode’s JSON-defined teams in order:

```text
1. Counter-Terrorists
2. Terrorists
```

`team_pick` must:

- validate the requested team
- reject picks after the intermission lock
- assign the human player to that team
- fill the player’s team to five actors with four NPCs
- fill the opposing team to five NPCs
- preserve the selected team across the round
- display a clear confirmation or rejection message

The server remains authoritative. The client command sends a request; the server validates and applies the team assignment.

The roster must be created before the countdown begins:

```text
INTERMISSION
  → team selection
  → roster locked
  → spawn actors
  → 3
  → 2
  → 1
  → GO
```

If no team is selected when intermission expires, use JSON-controlled fallback behavior. Default fallback: assign the player to the team with the fewer selected human players, then use Counter-Terrorists on a tie.

Reuse:

- existing `ServerGamemodeState::matchTeams`
- existing participant descriptors
- existing actor lifecycle and spawn paths
- existing terminal command registration

Do not create a separate Counter-Strike roster system.

## Stage 3 — Implement round and match lifecycle

Add a generic round lifecycle to the existing gamemode runtime:

```text
INTERMISSION
  → FREEZE_TIME
  → COUNTDOWN
  → ACTIVE
  → ROUND_RESULTS
  → next round or MATCH_RESULTS
```

Default Counter-Strike values:

```text
intermission: 30 seconds
freeze time: 0 seconds initially
countdown: 3 seconds
round time: 115 seconds
round win threshold: 8 rounds
maximum configured rounds: JSON-controlled
```

During an active round:

- actors do not respawn
- dead actors enter spectator/dead state
- dropped bomb remains in the world
- round ends on elimination, bomb explosion, bomb defuse, or timeout
- the next round resets actor lives, inventory, objective state, and spawn positions

At round end, display:

```text
Counter-Terrorists win the round
Counter-Terrorists 7 - Terrorists 3
```

The team names and score ordering must come from the active gamemode JSON. The left/right score order is fixed by the mode’s team array.

At match end:

```text
Counter-Terrorists win the match
```

Then return to the configured intermission and start the next match automatically.

Modify:

- `src/network/server-gamemode.h/.cpp`
- `src/game/gamemode-manager.h/.cpp`
- existing match HUD and results rendering
- replicated match-state packets as required

Add explicit round state/version fields so stale round packets cannot revive a previous round.
