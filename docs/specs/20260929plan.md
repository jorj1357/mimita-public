The behavior should be:
1. Camera direction becomes a desired orientation only.
2. The system computes orientation error.
3. Error becomes torque/angular velocity—not a snapped transform.
4. Head and torso receive the primary look torque.
5. Joint constraints transmit reaction forces into arms, legs, and torso.
6. Every part keeps its own linear and angular velocity.
7. A rapid right-to-left look change produces opposite angular momentum through the body.
8. World collisions and attached limbs can redirect that momentum naturally.

Plan: aimbody physical mode (active ragdoll during normal play)
Verified facts and discrepancies
- The physical aim controller already exists: aimAtCamera (src/ragdoll/ragdoll-mode.cpp:629-653), a damped velocity controller for head+torso, tuned by config/ragdoll.json (head.rotation_strength, torso_look_spring, look_damping). Your applyPhysicalAim is a rework of this.
- Joint momentum transfer already exists: solveJoints (ragdoll-mode.cpp:677-726) → solvePointJointVelocity (physical-body.h:74). §7 is already implemented.
- Normal play has no dynamic body: physicalBody.parts are a spring-smoothed kinematic collider/hitbox set (player-animation.cpp:525-559, player.cpp:157-205). The skeleton root is player.pos + yaw only (player.cpp:139-149,165).
- RagdollModeSystem::update is called from exactly one site, gated on G (src/sim/simulate-tick.cpp:68-98). One 60 Hz tick is simulateTick → physicsMainUpdate (simulate-tick.cpp:96, physics-mini.cpp:340).
- Client damage hitboxes use the real spring-smoothed worldTransform (weapon-fire-raycast.cpp:182,257,361). The server reconstructs hitboxes from a static default-pose template rotated by yaw (server-body-template.cpp:161-252, server-attack.cpp:89-109). They only agree at default pose.

Target architecture
An "active ragdoll" layer for normal play:
movement controller (authoritative: player.pos/vel/yaw)
        │ kinematic tether (rootOffsetLocal spring)
        ▼
physical RagdollBody: torso(torque) + head(torque) + arms/legs via joints
        │ integrate → joints → world collision → self-collision → joints
        ▼
write physicalBody.parts[].worldTransform + perfectPoseSkeleton  (render + client hitboxes)
player.pos/vel are NOT overwritten
Torso is dynamic but tethered to the authoritative root via the existing rootOffsetLocal mechanism; it may lag/sway but the root never moves from the body. No orientation snapping (body.orientation = desired is never used).
