# Open Gameplay Issues

## Purpose and audience

This is the short index of current gameplay issues, verification work, and
explicitly deferred design items. Each issue points to its behavior owner and
records whether the current spec already defines the expected behavior.

**Audience:** the player and contributors triaging gameplay work.

**Does not:** replace owner specifications, prove a fix, or decide product
behavior that is still unclear. Detailed implementation and runtime evidence
remain in the linked specifications, changelogs, scenarios, and run journals.

## Status and evidence

- **Active:** a current report or agreed work remains open.
- **Needs recheck:** an older report has no current reproduction.
- **Needs spec:** intent is known but its owner contract needs definition.
- **Verify:** an implementation or correction exists, but acceptance is
  incomplete.
- **Deferred:** intentionally kept at low priority.
- **Archived:** not current work; reopen only with new evidence or a new
  decision.

Use runtime scenarios and structured journals to verify measurable behavior.
Build success alone is not behavior evidence. Human review remains final for
visual quality and subjective feel. For every active issue, cite the precise
owner requirement or record that the requirement is missing or unclear.

Priority order: **P0** is the current top project goal; **P1** is active
blocking or high-impact work; **P2** is lower-priority follow-up or recheck;
**P3** is explicitly deferred.

## Issue details

### OGI-001 — Zombie Tower is the top project priority

The target is a complete playable mode, not only a prototype slice. Use the
Zombie Tower owner spec for progression, encounters, checkpoints, NPC roles,
failure/success, authored content, and full-run acceptance. Griever work belongs
under this goal. The current v1 contract requires at least 50 floors; a newer
design note asks whether the target should be 100. Keep that choice open here.
No completion or runtime acceptance is claimed.

### OGI-002 — Shared multi-floor NPC navigation

The user reports that Hospital NPC pursuit still stalls across floors. NPCs
should be capable of planning complex routes across multiple levels, including
routes with no straight walkable path, and should use role-available movement
such as jumping, dashing, or rocket jumping through shared actor movement.
Hospital and Zombie Tower are acceptance cases. When no legal route exists, the
NPC should report the unreachable goal instead of grinding into geometry.

The NPC movement spec already covers multi-floor navigation, traversal links,
ability filtering, stuck recovery, and corners. This is a current behavior
failure against existing requirements, with the requested capability clarified
in the Hospital issue section of that spec.

### OGI-003 — Actor sinking, crowd pinning, and closed geometry

The latest report says NPCs sink under actor-to-actor pushing, get forced into
corners or spawn areas, and enter a block beside CT spawn on Dust2CyberiaV4.
T-side NPCs are also pushed into their spawn side. The player reports related
ground sinking for human actors. Treat actor-pair collision, static-world
containment, navigation, and recovery as separate possible failure stages;
do not assume one root cause.

The NPC behavior spec already requires actor-pair no-pinning and final-pose
world containment. The Entity Editor spec says authored static blocks are added
as render geometry and collision triangles on both client and dedicated server;
entering a closed authored block is therefore a spec violation. The 2026-11-01
collision changelog records an earlier
recovery fix and a short NPC soak, but the new observation means the behavior
is not accepted as fixed. The older mace recording also showed NPC downward
recovery and player/server falling; exact playback remained blocked. See
[the recovery changelog](../changelog/2026-11-01/20261101_021333-npc-recovery-and-player-final-pose.md)
and [the recording-evidence changelog](../changelog/2026-11-01/20261101_013738-meleemace-recording-evidence.md).

Acceptance: no actor sinks or remains trapped under crowd pressure; actors do
not enter closed world blocks; contact/recovery events identify the first
incorrect step; valid movement out of corners remains possible. Run player and
NPC cases separately and preserve the fixed-tick collision path.

### OGI-004 — Reliable bounce across contact types

The user's desired behavior is reliable bounce whenever a physical impact
occurs: weapon against world, actor against world, actor pairs, turning or
steering while in contact, and finite edges/corners. The movement spec now
records this target. Collision architecture already smooths edge features and
uses configured response, but did not define a minimum bounce requirement across
all these contact classes. Response magnitude and sustained resting-contact
tuning remain open.

### OGI-005 — NPC combatants remain visible

A fresh report says NPC meshes disappear in Fun Counter Strike while the actors
continue damaging the player. The NPC behavior spec now says an active living
combatant must not silently lose its model; ordinary frustum and world
occlusion still apply. Capture the actor identity and the first divergence
between authoritative state, client entity/snapshot, model binding, and render
state. Human review must confirm the visible result.

### OGI-006 — Fun Counter Strike spawns only its configured roles

The user reports that a Normal Zombie appears at the player's spawn in Fun
Counter Strike. The mode spec defines its respawning Terrorist/Counter-Terrorist
roles and team spawns; a Normal Zombie at that spawn appears inconsistent with
the mode contract. Runtime evidence is missing. Record the mode configuration,
resolved role/team, spawn source, actor ID, and first spawn event before
changing roster or spawn logic.

### OGI-007 — Map Editor crash and bomb-site dragging

A fresh report says the Map Editor crashed and bomb-site handles do not drag
reliably. The Entity Editor spec already promises shared selection and drag
behavior for authored sites. The report is a possible implementation regression;
the crash and the drag failure may be independent. The supplied screenshot is
preserved at [image-7.png](image-7.png). Record the active map, selected site,
editor state, and first diagnostic before proposing a fix.

### OGI-008 — Bomb-site visibility in Entity Visibility

The request is that bomb sites are visible when Entity Visibility is enabled.
The Entity Editor spec did not explicitly include bomb-site zones in the
map-object visibility category. It now requires labeled circular zones to be
visible by default when the local viewer enables the master and map-object
category; the master switch itself remains off by default.

### OGI-009 — Fun Counter Strike interactions

The interaction implementation has partial runtime evidence, not full
acceptance. The 2026-11-01 changelog records a plant start and a release
interruption; full plant completion, defuse, NPC behavior, multiplayer,
editor save/reload, and visual review remain open. Keep this active as requested.
See [the interaction changelog](../changelog/2026-11-01/20261101_044651-funcounterstrike-bomb-interactions.md).

### OGI-010 — Complete scenario recordings

The recording spec already requires finalized files, valid headers/footers,
server tracks, and explicit failure for incomplete evidence. The open request
adds that no manual merge, cleanup, or repair should be needed and that a
readable summary should accompany the raw recording. Completion is not claimed
until a real recording can be consumed by analysis and playback without manual
repair.

### OGI-011 — JSON fields and references

The user wants a clear inventory of supported JSON fields and validation that
finds removed or unknown references, including a removed movement preset still
used elsewhere. The existence of individual validators is not proof that all
runtime-loaded fields, cross-file references, and accepted values are covered.
The JSON configuration architecture now records this as a cross-family
validation target. Keep runtime loader and offline validation behavior aligned;
coverage remains unverified.

### OGI-012 — Automatic validation runner

Combine the request for automatic config/gameplay checks with event-driven
scenario completion. The runner should report the expected result when the
configured success/failure event occurs and retain a bounded timeout for a
missing event or hang. Preserve build, runtime journal, and human-acceptance
evidence as separate results. The quality-gates spec now records this target;
implementation and runtime proof remain open.

### OGI-013 — Dev-loop structure

The user wants the large Python dev-loop entry point split into focused Python
modules. Keep this as maintainability work after the validation behavior is
defined. Preserve current profiles, process ownership, status/control paths,
and launch behavior. The quality-gates spec already requires a dev_loop package;
the current scripts tree has no such package, so this remains an implementation
gap.

### OGI-014 — NPC combat needs a current recheck

Older TDM reports say NPCs may stop attacking after one death, fail to engage
nearby targets, or not adopt live behavior-profile changes. These remain
unconfirmed, so do not call them fixed or current regressions without a fresh
TDM run. The user asked to retain them as needs recheck.

### OGI-015 — Spawn-point coverage needs a current recheck

The Entity Editor spec records that initial join, respawn/map change, and
npc_spawn can use different point-selection paths, and sets one server-owned
policy as the intended design. Keep the old report as needs recheck until the
documented acceptance cases are run.

### OGI-016 — VS Jason verification

The original report blamed live JSON loading. The diagnosis found that the
mode config loaded and a preset mismatch caused the unexpected FOV/movement;
the correction and config-resolution journal are recorded in the linked
changelog. Only visual FOV and movement feel remain to verify. Close the
original report after that check, not before.

Melee is still an improvement area but is not a priority now. Godball and HAFS

distribution. Human feel review remains open.
