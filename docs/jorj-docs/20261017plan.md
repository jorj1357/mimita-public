## Phase 2 — Animation format migration + phase sampling + Falcon poses

Goal: version-2 quaternion animation runtime, phase retiming, and real distinct
Falcon phase poses (spec `animations.md`).

2.1 Canonical quaternion channels (`src/entities/player.h`,
`player-animation-config.cpp`):
- Replace the transient Euler field with a canonical normalized quaternion per
  keyframe part: add `glm::quat rotationQuat`; keep `rotation` (Euler) only as a
  parse input.
- New small owner (e.g. `src/entities/animation-rotation.h/.cpp`):
  `eulerXyzDegreesToQuat` (compose `qx*qy*qz`), `normalizeQuatOrLast`,
  `isFiniteQuat`, `eulerDegreesFromQuat` (XYZ order, wrap `[-180,180)`).
- Parse rules: version 2 requires exactly one of `rotationEulerDegrees` /
  `rotationQuaternionWxyz`; reject both/neither; validate finite/non-zero;
  missing `version` and version 1 maps legacy `rotation` Euler → quaternion.
  Preserve last valid pose and emit one bounded diagnostic on failure.

2.2 Interpolation + pose composition (`src/entities/player-animation.cpp`):
- Replace rotation `glm::mix` (lines 118–120) with easing-then-shortest-arc
  SLERP; keep translation/scale curves unchanged.
- `poseMatrix` (lines 23–31) builds from quaternion → mat4; preserve
  `localTransform = restLocal * poseMatrix`.
- Convert overlay blends (dash/freeze/weapon poses) to the same canonical
  quaternion path so no mixed representation remains.

2.3 Phase sampling + action override:
- Add `samplePhase(clip, phaseTick, phaseTicks)` implementing
  `phaseProgress`/`clipSample` (`animations.md:284-317`); one-tick phase holds
  start pose; final phase tick reaches authored end pose.
- Route Melee actions through the explicit override in `Player::playOneShot`/
  action path: a new accepted move cancels the current clip at that tick and
  starts at clip tick 0; canceled clips emit no later audio markers.
- Wire `attack`/`hurt`/`death` states from `AvatarStateMap`.

2.4 Falcon pose clips: `assets/avatars/captainfalcon/animations.json`
(version 2, six canonical parts) with distinct windup/active/recovery clips per
action (punch, double-punch, Falcon Punch, air kick, forward dash, uptilt,
up-kick, up-special, sweep, down-kick, down-strike, shield, grab). Non-polished
one-pose/2-keyframe clips are acceptable.

2.5 Diagnostics + tests: `anim.set.loaded`, `anim.state.changed`,
`anim.clip.missing`, bounded `anim.part.sample`; pure-model golden fixtures

multiplier `1 - remainingFraction`; shield damage = move percent unless
overridden; no percent spill; break applies scaled knockback + fixed 5 m/s up;
natural expiry same break; broken recovery 0→full over 120 ticks;
release-before-break configurable release-recovery (provisional default,

5.2 Grab: E action with animated, limb-attached sphere hitbox (radius 1 m /
diameter 2 m); swept overlap; pull target toward animated anchor over JSON
duration respecting collision; target stays fully controllable (no
freeze/hold/mash-escape); strength scales with attacker speed and closeness to
sphere center; inherited-velocity limit curve (provisional: 20 m/s @0 %, 40
@100 %, 80 @300 %, capped ~120 @999 %, editable); 300-tick anti-chain-grab
immunity.

## Phase 7 — Prediction-first networking + referee

7.2 Server referee on bounded lag history: reject impossible cases (illegal

7.4 Revision alignment: replicate stable moveset revision/hash + actor
generation + action instance + input order + phase tick; activate a hot-reloaded
revision at a fixed-tick boundary for new actions only; keep client/server
aligned before accepting new-revision actions; preserve last valid config on

`MeleeHitEventPacket` path rather than adding per-move packets.
