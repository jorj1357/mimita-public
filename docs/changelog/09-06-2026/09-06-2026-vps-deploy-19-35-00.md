## Backup cron fix

**Root cause:** The cron ran `sudo -u postgres pg_dumpall -h localhost -U postgres` which forced TCP connection with md5 auth. The postgres user's `.pgpass` file was not being read in the cron environment (likely different HOME), causing `pg_dumpall` to block waiting for a password that never came. The cron reported "completed successfully" because the shell redirection created the empty file before pg_dumpall produced any output.

**Fix:** Removed `-h localhost -U postgres` so `pg_dumpall` uses Unix socket peer authentication via `sudo -u postgres`.

**Before:** `sudo -u postgres pg_dumpall -h localhost -U postgres | gzip > ...` (broken since Sep 4)
**After:** `sudo -u postgres pg_dumpall | gzip > ...` (works)

**Verification:** Manual test produced 587-byte valid gzip backup (same size as pre-Sep-4 backups).
