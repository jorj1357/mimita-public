# NPC fire intent repair

Date: 2026-09-24 16:25:50 EST
Branch: current working branch

## Result

PASS_WITH_HUMAN_REVIEW. NPCs now produce fire intent whenever they have a
hostile target and an equipped weapon runtime with ammunition. This removes the
state-machine gap where equipping worked but Idle/Aim/Hold/Strafe-style states
could leave `attack` false forever. `NpcCombat::tryFire` remains the owner of
cooldown, reload, line-of-sight, aim, ammo consumption, projectile/hitscan
execution, and damage application.

## Changed

File: `src/npc/npc.cpp`, `NpcSystem::updateOneNpc`, after bomb-tag action
handling and before navigation.

Old behavior: `computeStateMovement` was the only source of the local `attack`
intent, and several valid target states returned without setting it.

New behavior: when the NPC is not in bomb-tag behavior, has a target, has a
resolved weapon definition, and has current or reserve ammo, `attack` is set
true. Existing combat validation is unchanged.

## Authority and hot reload

The NPC loadout/equip path and damage path were already present. The missing
step was the actor action intent between them. The patch is small and preserves
the existing fixed-tick flow. The current hot actor module owns movement and
emotion decisions but does not yet expose NPC fire intent as a hot command, so
the repaired bridge is source-level behavior in the NPC owner; moving this
specific decision fully behind the generic hot actor command surface remains a
follow-up.

## Evidence

- Source evidence: `NpcSystem::updateOneNpc` reaches `NpcCombat::tryFire` only
  when `attack` is true; the new bridge supplies that intent for targetable,
  armed NPCs.
- Damage evidence: existing `NpcCombat::tryFire` calls the shared weapon fire
  path, and server NPC processing forwards resulting player damage through the
  authoritative server damage policy.
