## What was requested

A gamemode in the JSON gamemode format that spawns waves of NPCs: round 1
spawns 1 NPC, round 2 spawns 2, and so on. Killing every NPC advances the
round. Dying ends the run, records the highest round reached, and resets to
round 1. Each wave is preceded by the existing 3-2-1-GO countdown so the player
is never dropped straight into a fight. Agreed decisions: solo run per player,
NPC count scales only (no per-wave difficulty ramp), and the best round is shown
for the run only (no persistence).

## Exact behavior notes

- Wave N enemy count = `max(1, wave_start_count + (N-1) * wave_increment)`.
- `beginNpcWave` wipes the previous wave (`npcs.clear()` +
  `NpcSystem::destroyAll()`), adds N fresh `ServerNpc` entries at the match
  anchor (`gamemodeSpawnPoint`), rebuilds participants, and runs the shared
  `beginMatchCountdown` (3-2-1-GO). The new entries are adopted into the
  simulated `NpcSystem` on the next server tick and positioned at their stored
  spawn position.
- Wave IDs are allocated from 100000 upward (above the startup `nextEntityId`
  range starting at 1000) and skip any existing key.
- `checkWaveConditions` records `waveBest[id] = max(best, waveNumber)` for every
  human participant each active tick, so the round the player died on is the
  recorded best. No living human player => run over; no living NPC => round
  cleared. NPC-state counting reuses the existing `ActorState` path.
- The run-over branch is additionally gated on `humanParticipants > 0`, so an
  empty server does not restart NPC-only runs forever after the last player
  leaves.
- `respawn_seconds: 0` makes the mode one-life for players and NPCs, so dead
  NPCs never respawn mid-wave and a dead player stays `Spectating` until the
  shared spawn reset revives everyone at the next run.
- Player chat receives `WAVE N - M ENEMIES` at each wave start and
  `<name> reached round X` for each player when the run ends.
- No protocol change: the wave number is surfaced through the existing chat and
  the shared countdown/results phases; `DuelStatePacket` was not modified.
