# Exact implementation changes

## File: `website/server/db.js`

- Lines: 17 (after `const { Pool } = pg`)
- Old content: no BIGINT type parser configured
- New content:
  ```js
  pg.types.setTypeParser(20, (val) => parseInt(val, 10))
  ```
- Reason: node-postgres returns PostgreSQL BIGINT (OID 20) as JavaScript strings by default to avoid precision loss. The C++ client's `parseStats()` throws `json.exception.type_error.302: type must be number, but is string` when it encounters `"0"` (string) instead of `0` (number). Adding this parser converts all BIGINT values to JavaScript Number, which is safe for game values (won't exceed 2^53).
- Why unrelated behavior is preserved: Only affects BIGINT deserialization. All other column types (integer, text, boolean, jsonb) are unaffected.

## File: `website/server/game-api.js`

- Lines: 38
- Old content: `playtime_ticks: "0",`
- New content: `playtime_ticks: 0,`
- Reason: `defaultStats()` returned `playtime_ticks` as a string `"0"` instead of number `0`. This created a type inconsistency for new users with no stats row.
- Why unrelated behavior is preserved: Only the literal value type changed. The field name and fallback semantics are identical.
