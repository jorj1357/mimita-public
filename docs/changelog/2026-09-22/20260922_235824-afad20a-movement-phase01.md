## Scope of this session

Phase 0 (establish the `afad20a` behavior reference) and Phase 1 (one hot
movement owner matching the `afad20a` fixed-tick order and ability-reset rules),
per the approved slice plan. Local player and NPC paths only; server authority,
prediction, replay, per-limb collision, animation restoration, and the shared
C++/JSON selector are deliberately deferred.

## Work performed

Phase 0 — `afad20a` oracle and parity harness (cold test code, no gameplay
ownership):

- Added `src/physics/movement/reference/movement-afad20a-reference.{h,cpp}`: a
  self-contained reconstruction of the `afad20a` movement step with its own POD
  structs and the effective `afad20a` source-preset constants. It encodes the
  `afad20a` order `gravity -> freeze -> down-dash -> [collision] -> contact
  reset -> walk -> dash -> jump`, plus the `pow(timer/duration, 4)` freeze
  pass-through, set-semantics down-dash, additive dash, and jump buffer/coyote.
- Added `src/physics/movement/reference/afad20a-parity-selftest.{h,cpp}`:
  drives the real hot `movement.main` through `GenericRuntime::runDomain` and
  compares it tick-by-tick against the oracle for collision-free movement math
  (fall, air dash, down-dash, freeze activation, air-strafe). Also writes
  deterministic oracle fixtures.
- Added CLI flags in `src/game/game-cli.cpp`:
  `--afad20a-reference-selftest`, `--afad20a-parity-selftest`,
  `--afad20a-gen-fixtures`.
- Generated `tests/fixtures/movement/afad20a/fall-and-strafe.json` from the
  oracle.

Phase 1 — one hot movement owner in `afad20a` order:

- `src/hot-reload/modules/movement-system.cpp` (`movement.main`, local player)
  and `src/hot-reload/modules/actor-movement-system.cpp` (`movement.actors`,
  NPC/server actors) were reordered to the `afad20a` fixed-tick order:
  pre-collision `gravity -> freeze -> down-dash`, then collision, then
  post-collision `contact reset -> walk -> dash -> jump -> speed clamp`.
- Ability reset now runs after the collision solve and before walk/dash, so a
  fresh press can fire on the same tick a ground/limb contact is reported. This
  is the direct fix for "standing dash/down-dash not repeatable".
- `movement-dash.cpp`: removed the v2.0.6 airborne dash-quality multiplier;
  dash is now the full additive ground/air impulse with no time-based cooldown.
- `movement-freeze.cpp`: replaced the piecewise-quadratic suppression with the
  `afad20a` model — hard-stop stored velocity on activation, then
  `pow(timer/duration, 4)` pass-through while held.
- `movement-air.cpp`: the projection-limited air branch now includes the air
  speed-gain multiplier, matching the `afad20a` air rule; both callers select
  that branch from `source_air_accelerate_bug_compatible`.
- `hot-movement-policy.h`: `restoreTouchAbilities` now also resets the freeze
  timer so contact restores full freeze strength.
- `config/movement/movement-source.json`: aligned to `afad20a` values —
  `air_max_wishspeed` 3.0 -> 2.0, `ground_dash_impulse` 20.0 -> 10.0,
  `air_dash_impulse` 20.0 -> 10.0, and added `"down_dash_mode": "set"` so
  down-dash replaces vertical velocity as in `afad20a`.
- `config/collision.json`: changed the pre-existing working-tree
  `groundResponse` from `"bounce"` to `"settle"`. `afad20a` ground contacts
  settle (floor recovery clamps upward velocity); bounce remains for non-ground
  contacts. This was required for the movement tests' ground-settling
  expectation once walk moved after collision.

## Limits

- This does not restore per-limb collision. Collision still uses the existing
  `collision.main` solver with socket/mesh-part-derived limb colliders, not the
  `afad20a` `Player::physicalBody.parts` sweep producer. Limb/weapon
  penetration and limb-triggered root correction are not fixed here.
- Freeze availability is still not persisted in the runtime-state envelope
  (there is no `freezeAvailable` field), so a re-press without contact is not
  rejected; only the freeze strength timer is reset on contact. Adding the field
  is deferred to avoid an unplanned ABI/state migration.
- Ground settling was restored by selecting `groundResponse: "settle"`; the
  bounce-vs-settle policy is a Phase 4 collision concern.
- Server human-player authority, prediction, and replay still use the cold
  `movement-step.cpp` orchestration; only local player and NPC/actor hot paths
  were reordered.
- Animation was not touched; it still runs in `POST_MOVEMENT`/`RENDER` after
  collision and has not been restored to the `afad20a` animation model.
- The shared C++/JSON `behaviorSource` selector remains per-owner; no unified
  parity-comparison mode was added.
