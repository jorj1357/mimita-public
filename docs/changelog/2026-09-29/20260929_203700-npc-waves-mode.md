# NPC Waves gamemode implementation

## Implemented

- Added `config/gamemodes/npc_waves.json` and the `npc_waves` entry in
  `config/onlinemodes.json`.
- Added JSON-owned wave policy: starting count, per-wave increment, 15-second
  intermission, countdown duration, wave banner duration, stagger toggle, and
  NPCs-per-fixed-tick.
- Added authoritative server wave state and lifecycle in
  `src/network/server-gamemode.cpp`:
  `WAITING -> INTERMISSION -> COUNTDOWN -> WAVE BANNER -> ACTIVE`, with the
  next wave beginning only after every NPC reaches a terminal dead state.
- Added one-life wave behavior: `respawn_seconds: 0` keeps dead NPCs dead for
  the current wave; the existing server NPC snapshot retains their death
  presentation.
- Added optional fixed-tick spawn batches, defaulting to 10 NPCs per tick.
- Extended `DuelStatePacket` and `CommunityMatchClient` with wave number,
  target/spawned counts, and banner visibility. Protocol version is now 37.
- Added the JSON-defined `waveText` element to the active
  `config/gui/gamemode-meta-gui.json` layout. The shared overlay renders it
  through the existing layout/reload path without hardcoded presentation.
- Added bounded server-side gamemode polling so wave tuning changes are picked
  up without restarting the server; active countdowns preserve their current
  anchor and apply changed policy at the next safe transition.

## Evidence

- JSON parsing: `config/onlinemodes.json`, `config/gamemodes/npc_waves.json`,
  and `config/gui/gamemode-meta-gui.json` parsed successfully with
  PowerShell `ConvertFrom-Json`.
- Build: `python build_agent.py` completed with `Status: SUCCESS`, return code
  0, after a clean generated-build directory.
- Headless runtime: the rebuilt protocol-37 executable started on
  `127.0.0.1:23580`, loaded `atdm`, ran the dedicated 60 Hz loop, and exited
  cleanly after the five-second timeout. No client joined, so no wave was
  expected to start.
- Human/visual acceptance: not performed in this session.
