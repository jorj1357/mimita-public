## What changed

### `devscripts/build_friction.py`

- Added `record_wait_incident(agent, wait)`.
- One exact `wait_id` maps to one `build-friction` issue.
- A later observation of the same wait appends an occurrence instead of creating
  a duplicate issue.
- The automatic issue carries the wait ID, kind, stage, reason, elapsed time,
  budget, start UTC, build ID, generation, source generation, and request IDs.
- The root dev-loop's dedicated `dev-loop-wait` identity is registered on first
  use so an automatic issue never fails for an unknown agent.
- Added `wake_reviewer(issue, wait)`, which queues one bounded
  `build-wait-reviewer` activation with codex/opencode fallback. The prompt says
  the reviewer must not edit source or claim another agent's files.

### `devscripts/dev-loop.py`

- Added `WAIT_ISSUE_SECONDS`, default 60 seconds, overrideable with
  `MIMITA_WAIT_ISSUE_SECONDS` only for deliberate testing.
- Added tracking for queued EXE build waits, active EXE build waits, and
  game-DLL build waits.
- Added `check_wait_budget()` to the main loop.
- At the budget, it creates the issue once for that wait occurrence and wakes
  one reviewer.
- It emits `dev-loop.wait.over_budget` and `dev-loop.wait.reviewer-wake`
  events, or `dev-loop.wait.issue-failed` with the error if recording fails.
- It does not block or fail the build loop when coordination is unavailable.

### `devscripts/agent_coord.py`

- Added `next --mode waiting`.
- Waiting work returns, in priority order:
  - issues missing required context fields;
  - tasks with missing or unproven evidence;
  - stale task proofs;
  - review-only work.
- Waiting work is read-only; it does not assign or claim anything.
- Existing `next --claim` behavior is unchanged.

### `devscripts/agent-wake.py`

- The wake prompt now requires proof-first completion:
  - inspect `proof status`;
  - use the pinned runtime journal, not build success, as behavior proof;
  - repair missing issue context with `issue readiness`/`issue context`;
  - use `next --mode waiting` while waiting;
  - never edit another agent's leased file;
  - never close behavior work without proven evidence or an exemption.

### Documentation

- `AGENTS.md`: added plan-mode coordination guidance. Plan mode remains
  read-only for repository/build/runtime changes, but coordination reads and
  host-permitted messages, replies, and issue suggestions are allowed and
  encouraged for planning.
- `AGENTS.md`: added the waiting repair rule.
- `docs/specs/dev-loop/agent-coordination.md`: documented waiting repair work
  and read-only `next --mode waiting`.
- `docs/specs/dev-loop/change-to-evidence-latency.md`: replaced the old

- `docs/specs/dev-loop/agent-wake.md`: clarified that wake starts a bounded
  agent activation, not a new human or elevated authority.
