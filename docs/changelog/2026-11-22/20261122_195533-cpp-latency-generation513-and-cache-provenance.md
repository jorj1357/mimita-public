# C++ latency: generation 513 and cache provenance

## Changes

- Added source-inventory cache provenance and process/module/watcher identity to `devscripts/source_manifest.py` inventory metrics. This distinguishes memory hits, persistent disk hits, and cold scans, and identifies the code/cache instance that produced the metrics.
- Updated the source-manifest cache tests to use repository-local `.dev/tmp` and cover cold, in-memory, and persistent inventory paths plus process/module identity.

## Limits and next step

This work adds observability but has not reduced build latency. Generation 513's object scan took 1.868s and its linker took 39.941s. The measured client-side wait (167.891s) exceeded the actual build duration (61.235s), mostly in polling sleep; this is a separate dev-loop wait-path problem. Next, reload the root daemon safely, verify provenance fields in a fresh true no-op request, then measure matched unchanged and single-source attempts. No game process was started or stopped by this change.
