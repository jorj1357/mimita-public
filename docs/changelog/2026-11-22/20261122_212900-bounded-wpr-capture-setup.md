# Bounded WPR CPU capture setup

## Request

Automate Windows Performance Recorder access so MiMITA CPU stacks can be captured, attributed to source, optimized, and verified with matched before/after evidence.

## Changes

- Added `devscripts/cpu-wpr-capture.ps1`, a fixed, demand-only elevated Task Scheduler helper for 12-second verbose CPU captures. The ordinary Codex process remains unelevated; setup/update use one UAC approval, and the task accepts no arbitrary command arguments.
- Added `docs/operations/performance/wpr-cpu-capture.md` with install, update, capture, analysis, and removal steps.
- Capture preflight requires at least 8 GiB free on C:, at least 2 GiB free physical RAM, and WPR not already recording. It writes timestamped ETLs and JSONL outcomes without deleting prior captures.
- The helper is installed as `C:\Program Files\MiMITA Diagnostics\cpu-wpr-capture.ps1`; task `MiMITA CPU Stack Capture` was registered and updated successfully. The status log is `.dev/perf-captures/capture-task.jsonl`.
- WPR status/start/stop commands now have 30-second, 120-second, and 300-second limits. The task has a 10-minute overall limit; a timed-out start triggers a bounded WPR cancel attempt.
