# Map Entity Editor Automatic Save

Time UTC: 2026-10-10T22:26:25.251Z
Branch: current working tree; no commit created.

## Request and implementation

The requested behavior was that `entity_add` and subsequent entity edits write
the active map JSON automatically, while direct JSON editing and reload remain
available.

Before this change, `src/terminal/map-entity-commands.cpp` mutated the live
`MapConfigRegistry` and printed `(use entity_save)` for creation/deletion, but
only the explicit `entity_save` handler called `MapConfigRegistry::save()`.

The command owner now calls a shared local `reportAutoSave()` helper after each
successful authoring mutation:

- `entity_add`
- `entity_move_here`
- `entity_set_position`
- `entity_set`
- `entity_delete`
- `entity_visibility`

Successful writes report `(auto-saved)`. A failed write reports that the change
remains in memory only. `entity_save` remains available as a manual retry or
explicit save command, and `entity_reload` remains the explicit JSON reload/
last-valid-state path.

`docs/specs/entity-editor/entity-editor.md` was updated so its commands and
examples no longer require `entity_save` after each mutation. It now documents
the automatic persistence flow and retains the manual command for retry/use by
humans editing the live registry.
