# Add dev launch modes

- Date: 2026-09-28 (UTC)
- Scope: dev-loop startup selection and automatic Infinite Dungeon Slayer start
- Result: PASS_WITH_HUMAN_REVIEW

## Behavior

`devscripts/dev-launch-modes.json` is now the small numeric launch table:

- `1` = current dev-loop behavior.
- `2` = Infinite Dungeon Slayer: adds `--procedural-mode
  infinite_dungeon_slayer` and `--no-npcs`.

The profile can select a mode with `"launch_mode": 1`, or the command line can
override it with `--launch-mode 2`. Future modes can be added as more JSON
entries without changing the Python launcher.

## Implementation

- `devscripts/dev-loop.py`: loads and validates the JSON launch table, prints
  the selected mode, appends its server/client argument arrays, watches the
  table for edits, and accepts `--launch-mode`.
- `devscripts/dev-profiles/npc-navigation.json`: explicitly records mode `1`
  as the unchanged default.
- `src/network/net_mode.h` and `src/network/net_mode.cpp`: add
  `--procedural-mode <id>` and `--procedural-seed <n>` server options.
- `src/network/server.cpp`: when the first player joins an automatically
  selected procedural server mode, queues the existing authoritative
  procedural start owner with the configured/default seed. The existing
  procedural start path performs room generation and the player teleport.
- `docs/regressions/2026-09-27/dev-loop-server-crash-looks-frozen-REG.md`:
  already records the prior fly-context server crash and its pointer-check fix;
  that lesson remains attached to this startup path.
