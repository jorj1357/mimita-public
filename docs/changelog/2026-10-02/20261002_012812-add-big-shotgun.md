## Result

Status: PASS_WITH_HUMAN_REVIEW

Added the `big_shotgun` weapon as native slot 16, immediately after the
hitscan rifle's slot 15. It reuses the shotgun model, pose, fire, reload, hit,
and retriggered sound path. Its active JSON tuning is 1.0 second fire delay,
100 pellets, 10 degree spread, 0.5 hitscan radius, 25 damage per pellet,
4.0 headshot multiplier, 0.03 shooter/victim knockback terms, 2.0 sound
volume, and 0.6 playback pitch.

## Exact changes

### Configuration

`config/weapons.json` gained `big_shotgun` with:

```json
"slot": 16,
"damage": 25.0,
"headshot_multiplier": 4.0,
"fire_delay": 1.0,
"pellet_count": 100,
"beam_thickness": 0.5,
"shooter_knockback": 0.03,
"victim_knockback": 0.03,
"victim_knockback_per_damage": 0.03,
"sound": {"shoot": "shotgunshoot", "volume": 2.0, "pitch": 0.6, "retrigger": true}
```

The viewmodel uses `assets/objects/weapons/mimita-shotgun-v1.glb` with
`[2.0, 2.0, 2.0]` scale. `config/weaponsets.json` appends it after
`hitscan_rifle` in the stable set.

### Shared implementation

- `src/combat/weapon-data.cpp` / `.h`: added and registered the slot-16
  builtin definition, including safe fallback values when JSON is unavailable.
- `src/combat/pellet-pattern.h`: raised the shared deterministic pellet cap
  from 16 to 100.
- `src/combat/weapon-fire-hit.cpp`: uses the shared cap for local pellet
  storage and clamps configured pellet count to it.
- `src/combat/weapon-types.h`, `src/combat/weapon-json-config.cpp`, and
  `src/combat/weapon-audio.cpp`: added a JSON-controlled base sound volume
  multiplier used by the existing retrigger event path.
- `src/network/network-weapons.cpp`: maps the new definition and native slot
  to the existing shotgun network family.

The authoritative generic hitscan path therefore evaluates all 100 pellets.
The separate legacy network shot-effect payload remains capped at 16 pellet
impact records; this is presentation metadata and does not cap authoritative
damage.

Specification finding: the written weapon spec defines weapons as shared
configurations and explicitly describes shotgun `shotCount` as multiple
hitscan rays. The user's exact 100-pellet request is more specific than the
older 16-pellet implementation cap, so the shared cap was raised rather than
adding a weapon-specific firing path. The phrase “pitch + playback speed
combined of 0.6x” was interpreted as the existing audio pitch/playback-speed
field set to `0.6`, with volume independently set to `2.0`.

## Runtime and human review

The active running process was left untouched. The new C++ registration cannot
enter that already-running executable without a later safe cold-build/restart,
so live weapon selection, model scale, pellet spread, recoil, damage,
knockback, audio loudness/pitch, and retrigger behavior remain pending human
runtime review on a newly built executable. Build success, if later obtained,
must be reported separately from that visual/gameplay acceptance.
