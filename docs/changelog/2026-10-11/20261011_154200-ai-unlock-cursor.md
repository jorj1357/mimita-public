- Type: spec-code disagreement

## Source changes

- `devscripts/dev-loop.py:1220-1225`: added the literal `--unlock-cursor` to
  the client-only launch argument list. The server argument list is unchanged.
- `src/main.cpp:121,224-225`: added a startup boolean and parses the new flag.
  No-argument and ordinary launches retain the existing default.
- `src/main-init.cpp:27,174,256-271`: after normal client initialization,
  applies the request through the canonical `MouseLock` owner and writes one
  bounded `GUI`/`IMPORTANT` `cursor.launch_policy` event containing the flag,
  lock state, and actual GLFW cursor mode. The existing
  `cursor.mouse_lock_set` event also records the owner transition.

Old/new contract:

```text
old client args: [exe, --room, code, --map, map, --name, name]
new client args: [exe, --room, code, --map, map, --name, name, --unlock-cursor]
old startup lock: MouseLock default true; no startup override
new startup lock: --unlock-cursor -> MouseLock::set(window, false)
```

Pre-existing edits in `src/main.cpp` outside the new flag declaration and
parser were preserved and are not part of this change.
