## Findings

1. **Unreachable launch handler:** `config/command-aliases.json` maps both `startmelee` and `melee` to `modestart 14`. `Terminal::executeInternal` expands aliases before command-registry dispatch, so the registered `startmelee` handler in `src/terminal/debug-commands.cpp` is shadowed. Its disconnected-server preset/start/join path cannot be reached by typing `startmelee`; the alias instead runs a numeric host-only mode switch. This is a confirmed dead command path and a likely cause of the confusing launch experience.
2. **NPC contact geometry misses:** In saved run `logs/2026-10-18/20261018_152357/events.jsonl`, the server recorded 13 `melee.action.start` events, 8 `melee.npc.sweep` events, zero `melee.hit` events, and every recorded NPC sweep was `hit=false`. The logged center-to-player distances were 2.25–5.29 m while the sphere radius was 0.7–0.9 m. `server-melee-actions.cpp` approximates the hitbox from the actor root and a named-part height; the NPC sweep does not use the animated limb trajectory. This explains the misses in this run; it does not prove all runs miss.
3. **Smash-profile conflict:** `supersmashbrosmelee.md` §12/§15 says Melee disables legacy down-dash and freeze. `config/movement/movement-smash.json` enables dash, down-dash, and freeze. This is a confirmed spec/config disagreement.
4. **Unequal NPC damage path:** The Melee spec requires players and NPCs to share percent and knockback. In `server-melee-actions.cpp`, a player hit on an NPC applies knockback but comments that percent is tracked only for players. This is a source/spec gap; this audit did not runtime-test NPC percent replication.
5. **Visible hitboxes and idle stutter:** The active Melee spec still lists the hitbox debug view as presentation work. Existing one-second authored-pose samples cannot prove or disprove frame-level idle stutter. Neither received human visual acceptance in this audit.

The generic NPC melee/hitscan branch was not classified as dead code: it may serve other modes. The Melee-specific action, NPC, and animation paths have active callers. The `npc-difficulty.json` movement preset is a fallback: `npc.cpp` first looks up the role's `movementProfileId`; the current saved journal does not establish the effective runtime movement preset, so no override claim is made.
