## Regression Occurrence 1

### Observed

Time: `2026-10-29T15:45:06Z`

Version: `v2.0.7`

During v2.0.7 melee development, testing was primarily one human client against
NPCs. The following combinations were not continuously validated:

- NPC vs NPC
- NPC vs player
- player vs NPC
- player vs player

The session used to report the melee failure also contained more than one
runtime owner in one journal, so its evidence could not prove which server owned
the result.

### Expected Behavior

Every weapon family works against every actor pairing, and the same result is
observed under local and degraded network conditions.

Minimum matrix:

| Attacker | Target |
|---|---|
| NPC | NPC |
| NPC | Player |
| Player | NPC |
| Player | Player |

Weapon families:

- mace
- swordsword
- chainsaw
- hitscan
- rocket/projectile
- deathball

Network profiles:

- local
- 50 ms
- 150 ms
- packet loss/reorder/jitter

### Actual Behavior

“Melee works” was inferred from one actor pairing. NPC/NPC and player/player
were not proven, and the mixed journal made the observed server authority
ambiguous.

### Why This Is Bad

A feature can pass a one-human-versus-NPC test while failing in PvP, NPC combat,
or under latency. The project then records a false acceptance and later treats
the resulting failure as a new bug.

### Specification

`docs/specs/dev-loop/quality-gates.md`

Relevant requirement:

The dev-loop must support one server and N clients, each with its own journal,
scenario, assertions, and network profile. The actor matrix is a required gate.

### Wrong Process

Testing process, not a single code line:

```text
one human client
  -> spawn NPCs
  -> attack NPCs
  -> record one journal shared by multiple processes
  -> declare melee working
```

### Confirmed Cause

No automated multi-client actor/weapon/network matrix existed. Scenario command
queues also targeted only the first live client.

Evidence:

- `devscripts/dev-loop.py:1441-1502` queues commands to `live_clients[0]`
- one `command_queue_path` per run
- the reported session journal contains a sandbox server and a client-local TDM
  runtime

### Attempted Fix

None yet.

### Corrected Process

2. add per-client journals linked by run/session IDs
3. add actor/weapon/network matrix scenarios
4. run the matrix before closing the melee authority regression
5. preserve each client's own journal as evidence
